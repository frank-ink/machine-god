# Q
What is the minimal Rust + SQLite schema to enforce the 8-stage CVIR promotion ladder with immutable receipts, deterministic admission hashes under 1000 permutation restarts, and zero unauthorized admissions — while keeping cross-row validation (predecessor chain, monotonic ticks, conflicting verdicts) out of SQLite CHECK and in a pure Rust evaluator?

# A
CVIR: Minimal Rust + SQLite reference architecture

Design: SQLite enforces structural integrity and append-only receipts. A pure Rust evaluator enforces the eight-stage promotion ladder, temporal ordering, conflict detection and authorization. Deterministic hashing makes decisions independent of insertion order.

Evidence: SQLite transaction semantics (2024–2026), RFC 8949 deterministic CBOR (2020), Rust proptest and Ascent (Sahebolamri et al., 2022). No published CVIR-specific implementation or successful 1,000-restart experiment is established.

1. SQLite schema
SQL

CREATE TABLE receipts (
  receipt_hash BLOB PRIMARY KEY
    CHECK(length(receipt_hash)=32),
  candidate TEXT NOT NULL,
  method_hash BLOB NOT NULL
    CHECK(length(method_hash)=32),
  tick INTEGER NOT NULL CHECK(tick>=0),
  stage INTEGER NOT NULL
    CHECK(stage BETWEEN 0 AND 7),
  verdict INTEGER NOT NULL
    CHECK(verdict BETWEEN 1 AND 3),
  evidence_hash BLOB NOT NULL
    CHECK(length(evidence_hash)=32),
  signer_id TEXT NOT NULL,
  signature BLOB NOT NULL
    CHECK(length(signature)>0)
) STRICT;

CREATE TRIGGER immutable_update
BEFORE UPDATE ON receipts
BEGIN
  SELECT RAISE(ABORT,'IMMUTABLE');
END;

CREATE TRIGGER immutable_delete
BEFORE DELETE ON receipts
BEGIN
  SELECT RAISE(ABORT,'IMMUTABLE');
END;

CREATE TABLE decisions (
  request_hash BLOB PRIMARY KEY
    CHECK(length(request_hash)=32),
  receipt_set_hash BLOB NOT NULL
    CHECK(length(receipt_set_hash)=32),
  decision_hash BLOB NOT NULL
    CHECK(length(decision_hash)=32),
  admitted INTEGER NOT NULL
    CHECK(admitted IN (0,1))
) STRICT;


Stage mapping: 0 MEASURE, 1 FALSIFY, 2 MATCHED_ABLATION, 3 VERIFIED_OUTCOME, 4 CAUSAL_CREDIT, 5 BOUNDED_ADMISSION, 6 REENTRY_TEST, 7 CONTROL_INFLUENCE.

Ingestion accepts structurally valid receipts in arbitrary order. Authentication and promotion occur separately.

2. Pure Rust admission evaluator
Rust

fn evaluate(
    request: &Request,
    receipts: &[Receipt],
    policy: &Policy,
) -> Decision {
    let mut rs = receipts.to_vec();
    rs.sort_by_key(canonical_bytes);
    rs.dedup_by(|a, b| canonical_bytes(a)
                           == canonical_bytes(b));

    if !sealed_snapshot(request, policy) {
        return Decision::Blocked(Reason::Incomplete);
    }
    if !all_authentic(&rs, policy) {
        return Decision::Blocked(Reason::Unauthenticated);
    }
    if !all_fresh(&rs, request.tick, policy.ttl) {
        return Decision::Blocked(Reason::InvalidTick);
    }
    if conflicting(&rs, request) {
        return Decision::Blocked(Reason::Conflict);
    }
    if !complete_ordered_chain(&rs, request) {
        return Decision::Blocked(Reason::MissingStage);
    }
    if !authorized(&rs, request, policy) {
        return Decision::Blocked(Reason::Unauthorized);
    }
    Decision::Admit
}


The helper predicates are specifications requiring implementation and testing, not supplied executable implementations.

Enforce tick[i] ≤ tick[i+1], matching candidate/method, valid PASS evidence, no applicable revocations and explicit authorization. Evaluate all relevant receipts within a frozen transaction.

4. Deterministic replay

Generate valid, stale, future, contradictory, revoked, duplicated and forged receipts.

For 1,000 fixed seeds:

Shuffle insertion order into fresh SQLite databases.

Restart Rust and reopen SQLite.

Evaluate identical sealed snapshots with fixed clocks and policies.

Compare canonical decision bytes, decision hashes and admission records.

Acceptance: 1,000/1,000 bitwise-identical results; zero unauthorized admissions.

Caveat: A test can demonstrate these properties for its generated corpus, not guarantee them universally. Full guarantees additionally require deterministic trusted inputs, complete snapshots and a correctly implemented evaluator.
