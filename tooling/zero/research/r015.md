# Q

# A
CVIR: Minimal SQLite + Rust admission gate

Finding: The minimal robust design combines SQLite structural constraints, two immutability triggers, and a deterministic Rust admission evaluator. Do not enforce stage order during receipt insertion: arbitrary insertion permutations would then produce different accepted datasets.

2. SQLite schema and triggers
SQL

CREATE TABLE receipts (
  receipt_hash BLOB PRIMARY KEY
    CHECK(length(receipt_hash)=32),
  candidate TEXT NOT NULL,
  method_hash BLOB NOT NULL
    CHECK(length(method_hash)=32),
  tick INTEGER NOT NULL CHECK(tick>=0),
  stage INTEGER NOT NULL
    CHECK(stage BETWEEN 0 AND 7),
  verdict INTEGER NOT NULL
    CHECK(verdict IN (1,2,3)),
  evidence_hash BLOB NOT NULL
    CHECK(length(evidence_hash)=32),
  signer_id TEXT NOT NULL,
  signature BLOB NOT NULL
    CHECK(length(signature)>0)
) STRICT;

CREATE TRIGGER receipts_immutable_update
BEFORE UPDATE ON receipts
BEGIN
  SELECT RAISE(ABORT,'immutable receipt');
END;

CREATE TRIGGER receipts_immutable_delete
BEFORE DELETE ON receipts
BEGIN
  SELECT RAISE(ABORT,'immutable receipt');
END;


PASS=1, FAIL=2, REVOKE=3.

These constraints reject malformed structure but cannot authenticate signatures, detect all cross-row contradictions or establish experimental causality.

3. Five admission predicates

Evaluate the complete, sealed receipt batch under BEGIN IMMEDIATE:

ADMIT = AUTHENTIC ∧ FRESH ∧ CONSISTENT ∧ COMPLETE ∧ AUTHORIZED

AUTHENTIC: Verify canonical signatures, signer authority, receipt hashes and evidence bindings.

FRESH: Enforce T−TTL ≤ tick ≤ T.

CONSISTENT: Reject conflicting verdicts or evidence within the same candidate/method/stage/tick scope.

COMPLETE: Require a valid eight-stage predecessor chain up to the requested stage, with monotonic ticks.

AUTHORIZED: Enforce promotion permissions, experimental scope and resource bounds.

Cross-row validation cannot be expressed through SQLite CHECK subqueries.

5. Deterministic replay

Test: cvir_permutation_restart_1000

For seeds 0..999, shuffle identical receipts into fresh databases, restart Rust, and compare canonical decision bytes, hashes and admission states.
