# Q
What is the minimal CVIR promotion-ladder gate set (MEASURE->FALSIFY->MATCHED_ABLATION->VERIFIED_OUTCOME->CAUSAL_CREDIT->BOUNDED_ADMISSION->REENTRY_TEST->CONTROL_INFLUENCE) implementable as deterministic SQLite CHECK constraints + triggers over a receipts table, such that a Rust process restart + 1000 seeded insertion permutations yields bitwise-identical admission hashes while rejecting stale, future, contradictory, and unauthenticated evidence?

# A
CVIR: Minimal deterministic promotion gate

Answer: Eight ordered promotion stages, five global admission predicates, immutable SQLite receipts and a canonical Rust decision function are sufficient under explicitly defined trust and snapshot assumptions.

Critical distinction: SQLite CHECK constraints and triggers enforce database invariants; cryptographic authentication and permutation-invariant admission require Rust. Receipt ingestion must be independent of insertion order.

2. Minimal SQLite schema
SQL

CREATE TABLE receipts (
  receipt_hash BLOB PRIMARY KEY
    CHECK(length(receipt_hash)=32),
  candidate TEXT NOT NULL,
  method_hash BLOB NOT NULL
    CHECK(length(method_hash)=32),
  tick INTEGER NOT NULL CHECK(tick>=0),
  stage INTEGER NOT NULL
    CHECK(stage BETWEEN 0 AND 7),
  verdict INTEGER NOT NULL
    CHECK(verdict IN (1,2,3)),
  evidence_hash BLOB NOT NULL
    CHECK(length(evidence_hash)=32),
  signer_id TEXT NOT NULL,
  signature BLOB NOT NULL
    CHECK(length(signature)>0)
) STRICT;

CREATE TRIGGER receipts_no_update
BEFORE UPDATE ON receipts
BEGIN
  SELECT RAISE(ABORT,'IMMUTABLE');
END;

CREATE TRIGGER receipts_no_delete
BEFORE DELETE ON receipts
BEGIN
  SELECT RAISE(ABORT,'IMMUTABLE');
END;


PASS=1, FAIL=2, REVOKE=3.

These constraints guarantee structural validity and immutability through ordinary SQL writes, not cryptographic trust. Use restricted database access and reject unauthorized writers.

3. Deterministic admission and hashing

Rust validates five predicates over a frozen BEGIN IMMEDIATE snapshot:

AUTHENTIC ∧ FRESH ∧ CONSISTENT ∧ COMPLETE_CHAIN ∧ AUTHORIZED

Use a fixed logical tick, TTL, policy version and trust-root set. Reject stale/future receipts, invalid signatures, contradictory evidence and missing prerequisites. A signed completeness watermark or sealed batch is necessary to distinguish absent evidence from evidence not yet delivered.

Canonicalize using RFC 8949 deterministic CBOR, fixed schema field order (prefer an array), u64be tick bytes and no floats.

4. Replay experiment

cvir_permutation_restart_1000

For seeds 0–999, insert identical receipts in shuffled order into fresh databases, restart Rust, and evaluate identical requests.

Assert bitwise equality of canonical decision bytes, hashes and admission states; assert zero unauthorized admissions.

Evidence status: SQLite (2024–2026), RFC 8949 (2020), Ascent (Sahebolamri et al., 2022) provide established building blocks. No published CVIR-specific 1,000-run result is verified.

Qualification: Determinism follows conditionally from identical logical inputs and pure evaluation. The specified replay test has not been executed; it cannot prove universal correctness.
