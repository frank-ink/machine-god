# Q
Can a bitwise-deterministic SQLite admission gate over CVIR receipts (canonical CBOR field ordering, u64be ticks, SHA-256 link chain) guarantee identical decision hashes across 1000 seeded insertion permutations and Rust process restarts while rejecting stale, future, contradictory, and unauthenticated evidence?

# A
CVIR deterministic admission: feasibility and proof conditions

Answer: Yes, conditionally. A Rust/SQLite admission gate can produce bitwise-identical SHA-256 decision hashes across 1,000 insertion permutations and process restarts while rejecting stale, future, contradictory and unauthenticated receipts.

However, canonical CBOR, u64be ticks and SHA-256 chaining are necessary design elements, not sufficient guarantees by themselves. Deterministic policy evaluation, snapshot completeness and fixed environmental inputs are equally essential.

Use a fixed-field array or deterministic CBOR map ordering. Reject duplicate map keys, indefinite lengths, noncanonical encodings, unknown schema versions and ambiguous identifiers.

Important: CBOR's ordinary integer representation is not fixed-width u64be. Encoding the tick as an eight-byte CBOR byte string explicitly resolves that distinction.

Sign the canonical payload excluding signature, with domain separation and pinned trust roots.

4. Replay test

cvir_permutation_restart_1000

Run 1,000 seeded insertion shuffles into fresh SQLite databases, restarting the Rust process for each run. Hold logical inputs constant; compare canonical decisions, hashes and admission states byte-for-byte.

Include stale, future, forged, contradictory, duplicate and incomplete evidence. Assert zero invalid admissions.

Pass criterion: 1,000/1,000 identical decision hashes and rejection reasons.
