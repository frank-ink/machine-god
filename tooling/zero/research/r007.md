# Q
Which minimal Datalog rule set (Ascent/Crepe) plus SQLite receipt schema binds CVIR promotion evidence to candidate, method and logical tick so stale, future or contradictory receipts are rejected by a fail-closed Rust admission gate, and which replay test proves that gate is deterministic?

# A
CVIR: deterministic, fail-closed admission

Design: SQLite stores immutable, authenticated evidence. Ascent (Sahebolamri et al., 2022; maintained 2024–2026) evaluates the promotion rules. Rust alone authorizes state transitions.

1. Minimal SQLite receipt schema
SQL

CREATE TABLE receipts (
  id TEXT PRIMARY KEY,
  candidate TEXT NOT NULL,
  method_hash BLOB NOT NULL,
  tick INTEGER NOT NULL CHECK(tick >= 0),
  stage INTEGER NOT NULL CHECK(stage BETWEEN 0 AND 7),
  verdict TEXT NOT NULL
    CHECK(verdict IN ('PASS','FAIL','REVOKE')),
  evidence_hash BLOB NOT NULL,
  signer TEXT NOT NULL,
  signature BLOB NOT NULL,
  UNIQUE(candidate, method_hash, tick, stage, evidence_hash)
);

CREATE TABLE admissions (
  candidate TEXT NOT NULL,
  method_hash BLOB NOT NULL,
  tick INTEGER NOT NULL,
  stage INTEGER NOT NULL CHECK(stage BETWEEN 0 AND 7),
  receipt_set_hash BLOB NOT NULL,
  PRIMARY KEY(candidate, method_hash, tick)
);


Stages: MEASURE(0) → FALSIFY(1) → MATCHED_ABLATION(2) → VERIFIED_OUTCOME(3) → CAUSAL_CREDIT(4) → BOUNDED_ADMISSION(5) → REENTRY_TEST(6) → CONTROL_INFLUENCE(7).

2. Minimal Datalog policy

Soufflé-style notation, directly translatable to Ascent; not literal Ascent macro syntax.

prolog

// E(c,m,t,s): authenticated PASS
// X(c,m,t,s): authenticated FAIL or REVOKE
// P(c,m,t,s): requested promotion

ok(c,m,t,0) :-
  E(c,m,t,0), !X(c,m,t,0).

ok(c,m,t,s) :-
  E(c,m,t,s),
  s > 0, s <= 7,
  ok(c,m,t,s-1),
  !X(c,m,t,s).

blocked(c,m,t,s) :-
  P(c,m,t,s), !ok(c,m,t,s).


All relations are evaluated over a frozen, complete receipt snapshot. If receipts can arrive late or be withheld, negation-as-failure is not sufficient; the gate must reject incomplete snapshots.

3. Rust admission gate

Before generating Datalog facts:

Verify signatures and evidence hashes.

Require exact candidate and method_hash.

Reject receipt.tick > current_tick and receipts older than the configured freshness window.

Reject conflicting PASS/FAIL/REVOKE receipts for the same stage and tick; never use last-write-wins.

Require a complete, authenticated snapshot and all prerequisite stages.

Write admission and receipt-set hash atomically with BEGIN IMMEDIATE; abort on contention or validation failure. SQLite supports transactional snapshot isolation. 
SQLite

Temporal qualification: The minimal Datalog rules above require all stages at the same logical tick. For multi-tick promotion, select validated predecessor receipts with predecessor_tick ≤ current_tick, enforce monotonic stage progression and reject revoked evidence.

4. Deterministic replay test

Test: cvir_replay_permutation_invariance

Generate a fixed corpus containing valid, stale, future, duplicated, contradictory and revoked receipts.

Run 1,000 seeded permutations against fresh SQLite databases, fixing logical clock, policy version, trust roots and initial state.

Assert:

SHA256(canonical_decisions || canonical_state) == reference_hash

Additionally assert:

Every invalid promotion is BLOCKED.

Every accepted promotion has its complete verified evidence chain.

Restart and replay produce identical decisions and state hashes.

No partial admission survives transaction failure.

Interpretation: Passing establishes deterministic replay for the tested corpus, not universal correctness. Property-based mutation and independent policy oracles remain necessary.

Status: Proposed design, not an implemented or experimentally verified CVIR gate. Ascent supports stratified negation; production behavior must be tested against the pinned engine version.
