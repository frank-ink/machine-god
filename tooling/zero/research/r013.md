# Q
What is the minimal set of CVIR promotion-ladder gates (MEASURE -> FALSIFY -> MATCHED_ABLATION -> VERIFIED_OUTCOME -> CAUSAL_CREDIT -> BOUNDED_ADMISSION -> REENTRY_TEST -> CONTROL_INFLUENCE) that can be implemented as deterministic SQLite CHECK constraints + triggers over a receipts table, such that a Rust process restart + 1000 seeded insertion permutations yields bitwise-identical admission hashes while rejecting stale, future, contradictory, and unauthenticated evidence?

# A
CVIR: minimal deterministic SQLite promotion gates

Conclusion: Eight sequential evidence gates plus five global integrity checks are sufficient for a minimal CVIR admission policy. However, SQLite CHECK constraints and triggers alone cannot authenticate cryptographic evidence or guarantee permutation-invariant admission.

Critical design choice: Separate receipt ingestion from promotion. Rejecting missing predecessors during INSERT makes outcomes depend on insertion order. Evaluate the complete evidence set only after a frozen batch is available.

2. Minimal SQLite constraints
SQL

CREATE TABLE receipts (
  receipt_hash BLOB PRIMARY KEY
    CHECK(length(receipt_hash)=32),
  candidate TEXT NOT NULL,
  method_hash BLOB NOT NULL
    CHECK(length(method_hash)=32),
  tick INTEGER NOT NULL CHECK(tick>=0),
  stage INTEGER NOT NULL
    CHECK(stage BETWEEN 0 AND 7),
  verdict INTEGER NOT NULL
    CHECK(verdict IN (1,2,3)),
  evidence_hash BLOB NOT NULL
    CHECK(length(evidence_hash)=32),
  signer_id TEXT NOT NULL,
  signature BLOB NOT NULL
    CHECK(length(signature)>0)
) STRICT;

CREATE TRIGGER immutable_receipt
BEFORE UPDATE ON receipts
BEGIN
  SELECT RAISE(ABORT,'IMMUTABLE');
END;

CREATE TRIGGER no_receipt_delete
BEFORE DELETE ON receipts
BEGIN
  SELECT RAISE(ABORT,'IMMUTABLE');
END;


Verdicts: PASS=1, FAIL=2, REVOKE=3.

CHECK handles local structure; cross-row dependencies require triggers or set-based queries. SQLite explicitly prohibits subqueries in CHECK expressions. 
www3.sqlite.org

3. Five global admission checks

Under BEGIN IMMEDIATE, Rust validates the frozen batch:

AUTHENTIC: Verify canonical signatures, signer authorization and evidence hashes.

FRESH: Reject tick > T or tick < T−TTL.

CONSISTENT: Reject contradictory verdicts and conflicting evidence for the same logical stage.

COMPLETE: Require all predecessor PASS stages, valid temporal ordering and no applicable revocation.

AUTHORIZED: Verify bounded scope, policy version and independent verifier requirements.

ADMIT ⇔ AUTHENTIC ∧ FRESH ∧ CONSISTENT ∧ COMPLETE ∧ AUTHORIZED

Persist the admission atomically. Trigger-based checks may reinforce these conditions, but must not depend on arrival order.
