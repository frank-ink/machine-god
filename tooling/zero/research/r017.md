# Q
What is the minimal async Rust architecture for a background reflex router that guarantees <50ms p99 latency on local wiki fact lookup while concurrently running scrape/search tools, writing all perception/events to a single SQLite unified.db without lock contention, and providing a deterministic replay log for CVIR admission evaluation?

# A
Async Rust reflex router: minimal architecture (2024–2026)

Design target: Local wiki fact retrieval below 50 ms p99, concurrent scrape/search operations, one SQLite unified.db, and reproducible CVIR admission replay.

Qualification: A hard p99 guarantee cannot be established from architecture alone. It requires measured hardware-specific latency, bounded workloads and admission control. In particular, SQLite WAL does not eliminate single-writer contention.

Key invariant: Reflex latency must not depend on scraper execution, network availability or SQLite writer acquisition.

Use separate bounded executor capacity for background blocking work; never let scrapers exhaust the threads needed by the reflex lane.

2. Minimal unified.db schema
SQL

PRAGMA journal_mode=WAL;
PRAGMA foreign_keys=ON;

CREATE TABLE events (
  seq INTEGER PRIMARY KEY,
  event_id BLOB NOT NULL UNIQUE,
  logical_tick INTEGER NOT NULL,
  kind TEXT NOT NULL,
  payload BLOB NOT NULL,
  payload_hash BLOB NOT NULL,
  prev_hash BLOB NOT NULL,
  chain_hash BLOB NOT NULL
) STRICT;

CREATE TABLE cvir_decisions (
  request_hash BLOB PRIMARY KEY,
  snapshot_seq INTEGER NOT NULL,
  policy_hash BLOB NOT NULL,
  receipt_set_hash BLOB NOT NULL,
  decision_hash BLOB NOT NULL,
  admitted INTEGER NOT NULL CHECK(admitted IN (0,1))
) STRICT;


Add append-only triggers, a separate immutable CVIR receipt table and authenticated snapshot-seal records.

Use one dedicated writer thread with a bounded Tokio mpsc receiver and rusqlite. Batch writes transactionally; assign seq and update the hash chain inside the transaction. Do not acknowledge durable event ingestion before commit.

SQLite WAL permits concurrent readers and a writer, but only one writer at a time.

Use deterministic CBOR (RFC 8949, 2020), canonical identifiers and fixed integer encodings.

Separate two ordering concepts:

Event log: Authoritative writer-assigned sequence; replay follows seq.

CVIR evidence set: Sort canonical receipts independently of arrival order before calculating admission hashes.

Freeze logical tick, policy version, trust roots and receipt snapshot before CVIR evaluation.

For asynchronous events, identical replay requires recorded external responses and a fixed event ordering. Scheduling alone cannot reproduce network timing.
