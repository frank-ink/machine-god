# Q
What is the minimal set of SQLite PRAGMA settings and Rust connection-pool configuration that guarantees single-writer serializability, zero reader-writer blocking, and crash-safe WAL checkpointing for a 500MB unified.db under 100 concurrent read-only connections, with measured p99 append latency < 1ms on NVMe?

# A
SQLite WAL + Rust: minimal configuration (2024–2026)

Verdict: No SQLite configuration simultaneously guarantees single-writer serializability, zero reader–writer blocking, crash-safe checkpointing and **p99 durable append latency
-- Initialization, before opening the pool
PRAGMA journal_mode=WAL;

-- Dedicated writer connection
PRAGMA synchronous=FULL;
PRAGMA wal_autocheckpoint=0;
PRAGMA busy_timeout=1000;
PRAGMA foreign_keys=ON;

-- Each read-only connection
PRAGMA query_only=ON;
PRAGMA busy_timeout=100;

-- Dedicated checkpoint connection
PRAGMA wal_checkpoint(PASSIVE);

Why: WAL supports concurrent snapshot readers and one writer. FULL synchronizes WAL commits for stronger power-loss durability; NORMAL retains database consistency but can lose recent commits. Disabling automatic checkpointing removes checkpoint work from the ordinary commit path.

3. Checkpoint reliability

Run PASSIVE checkpoints periodically; inspect checkpoint status and WAL growth. Schedule RESTART or TRUNCATE only when readers are drained.

Critical limitation: Persistent readers can prevent checkpoint completion indefinitely. Even WAL readers may encounter blocking during recovery or certain checkpoint operations.
