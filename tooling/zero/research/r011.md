# Q
How to design a bitwise-deterministic CVIR admission gate over SQLite receipt tables that guarantees identical decision hashes across 1000 seeded shuffles and process restarts, including canonicalization of field order, integer encoding, and hash chaining?

# A
CVIR: Bitwise-deterministic SQLite admission gate

Objective: Identical logical receipt sets produce bitwise-identical admission decisions across insertion permutations and Rust process restarts.

Architecture: SQLite → canonical receipts → signature verification → conflict detection → Ascent/Datalog policy → Rust fail-closed gate → canonical decision hash.

Use fixed binary encoding, not SQLite row serialization.

Reject malformed encodings, unsupported versions, ambiguous identifiers and overflow. Sign canonical fields excluding signature; pin verification algorithms and trusted signers.

Receipt identity:

RID = SHA256("CVIR-RID-V1" || LP(signed_payload) || LP(signature))

Verify receipt signatures and evidence bindings.

Reject stale (tick < T−TTL) and future (tick > T) receipts.

Detect contradictory verdicts sharing (candidate, method_hash, tick, stage).

Deduplicate byte-identical receipts only.

3. Fail-closed Rust admission

Freeze logical_tick, TTL, policy version, trust roots, candidate, method and requested stage.

Ascent (Sahebolamri et al., 2022) evaluates the eight-stage CVIR prerequisite chain using authenticated facts.

Admission invariant:

ADMIT ⇔ AUTHENTIC ∧ FRESH ∧ CONSISTENT ∧ COMPLETE ∧ POLICY_PASS

Use deterministic collections (BTreeMap, BTreeSet), fixed rejection-reason precedence, and atomic SQLite transactions.

4. Replay verification

Test: cvir_permutation_restart_1000

For seeds 0–999:

Shuffle identical receipt bytes into fresh SQLite databases.

Restart the Rust process.

Execute identical admission requests.

Compare canonical decision bytes, hashes and admission-state hashes.

Assert that stale, future, contradictory and unauthenticated evidence never authorizes promotion.

Pass criterion: 1,000/1,000 identical results and zero unauthorized admissions.

References: SQLite transaction isolation (2024–2026); Ascent (2022); RFC 8949 deterministic CBOR (2020); Rust proptest (2024–2026).

Qualification: Canonicalization guarantees permutation invariance only when policy evaluation is deterministic and the logical receipt set and environment are identical. The 1,000-run test verifies this property empirically for its corpus; it is not a universal proof.

Status: Proposed architecture; no independently verified published CVIR-specific implementation or passing replay results.
