# Q
What is the minimal SQLite WAL + Rust connection pool configuration that achieves p99 durable append latency < 1ms on NVMe for a 500MB unified.db with 100 concurrent read-only connections, including crash-safe checkpointing and zero reader-writer blocking?

# A
SQLite WAL + Rust: minimum viable configuration

Verdict: No published configuration guarantees all requested properties simultaneously: **p99 durable append
-- Initialize once, before starting workers
PRAGMA journal_mode=WAL;

-- Dedicated writer connection
PRAGMA synchronous=FULL;
PRAGMA wal_autocheckpoint=0;
PRAGMA foreign_keys=ON;
PRAGMA busy_timeout=1000;

-- Each read-only connection
PRAGMA query_only=ON;
PRAGMA busy_timeout=100;
PRAGMA cache_size=-2048;

-- Dedicated maintenance connection
PRAGMA wal_checkpoint(PASSIVE);

FULL provides stronger power-loss durability by syncing the WAL at commit. NORMAL may improve latency but sacrifices durability of recently committed transactions after power failure.

3. Crash-safe checkpointing

Use a separate maintenance connection:

PASSIVE checkpoints during normal operation.

Monitor checkpointed versus remaining WAL frames.

Use RESTART or TRUNCATE during controlled reader-drain windows.

Never delete -wal or -shm files manually during database operation.

Verify recovery with abrupt process termination and power-failure simulation.

PASSIVE avoids waiting for readers but cannot guarantee checkpoint completion. Long-running readers can cause unbounded WAL growth.
