# Q
What minimal set of Hypothesis strategies and metamorphic mutations (status escalation, evidence deletion, receipt substitution, capability-ID mismatch, issue-number substitution, deleted anchors, duplicate headings, URL encoding, Markdown link syntax) achieves 100% mutation score against a fail-closed Markdown capability-ledger checker while maintaining zero false positives on the repository's own documentation corpus?

# A
**Minimal mutation-adequate strategy set (uncertain: specific checker impl unknown; based on CommonMark + capability-ledger threat model):**

**Hypothesis strategies (composite):**
- `valid_ledger() = st.builds(Ledger, capabilities=st.lists(capability(), min_size=1), receipts=st.lists(receipt()), issues=st.lists(issue_ref()))` where `capability() = st.builds(Capability, id=cap_id(), status=st.sampled_from(STATUSES), evidence=st.lists(evidence_ref()))`
- `cap_id() = st.from_regex(r"CAP-[A-Z]{3}-\d{4}", fullmatch=True)`
- `receipt() = st.builds(Receipt, hash=st.from_regex(r"sha256:[a-f0-9]{64}"), payload=st.dictionaries(st.text(), st.text()))`
- `issue_ref() = st.builds(IssueRef, number=st.integers(1, 99999), repo=st.just("owner/repo"))`

**Metamorphic mutations (9 operators → 5 strategy composites for 100% score):**

| Composite | Mutations covered | Strategy |
|-----------|-------------------|----------|
| `escalate_status` | status escalation | `ledger.map(lambda l: l._replace(capabilities=[c._replace(status=escalate(c.status)) for c in l.capabilities]))` |
| `delete_evidence` | evidence deletion, deleted anchors | `ledger.map(lambda l: l._replace(capabilities=[c._replace(evidence=[]) for c in l.capabilities]))` |
| `substitute_receipt` | receipt substitution, capability-ID mismatch | `ledger.flatmap(lambda l: st.tuples(st.just(l), st.sampled_from(l.receipts), receipt())).map(apply_subst)` |
| `substitute_issue` | issue-number substitution | `ledger.map(lambda l: l._replace(issues=[i._replace(number=i.number+1) for i in l.issues]))` |
| `syntax_perturb` | duplicate headings, URL encoding, Markdown link syntax | `ledger.flatmap(render).flatmap(markdown_mutate).map(parse)` where `markdown_mutate` applies: heading duplication, `%2F`/`%23` encoding, `[text](url)` ↔ `[text][ref]` + `[ref]: url` |

**Oracle:** Fail-closed checker must reject all 5 mutated variants; accept all `valid_ledger()` outputs. **Zero-FP guard:** Run corpus through `valid_ledger().filter(lambda x: x in corpus)` — must pass unchanged.

**Key refs:** MacIver 2013 (Hypothesis); Chen et al. 1998 (metamorphic); Jia & Harman 2011 (mutation testing); CommonMark 0.30 (2019); OWASP Input Validation 2023. **Uncertainty:** Assumes checker validates *semantic* ledger invariants (ID binding, receipt integrity, issue traceability) not just syntax. If checker only validates AST well-formedness, `syntax_perturb` alone may suffice.
