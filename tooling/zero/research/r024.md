# Q
What is the minimal set of SQLite PRAGMAs and Rust connection pool settings (sqlx/rusqlite + deadpool) that guarantee p99 durable append latency < 1ms on NVMe for a 500MB unified.db with 100 concurrent read-only connections, including crash-safe checkpointing and zero reader-writer blocking, validated by a reproducible fio/io_uring benchmark?

# A
**SQLite PRAGMAs (minimal set, `PRAGMA` = persistent unless noted):**
```sql
PRAGMA journal_mode = WAL;           -- mandatory for zero reader-writer blocking
PRAGMA synchronous = NORMAL;         -- durable on NVMe (power-loss atomic sector write), p99 < 1ms [1]
PRAGMA wal_autocheckpoint = 0;       -- disable auto; checkpoint manually via dedicated connection
PRAGMA busy_timeout = 5000;          -- ms; defensive, rarely hit with WAL
PRAGMA mmap_size = 536870912;        -- 512MiB ≥ db size; read-only connections map entire DB
PRAGMA page_size = 4096;             -- match NVMe sector/cluster; set at DB creation only
PRAGMA cache_size = -32768;          -- 32MiB page cache (negative = KiB); fits hot pages
PRAGMA temp_store = MEMORY;          -- avoid temp file contention
PRAGMA locking_mode = NORMAL;        -- default; EXCLUSIVE breaks concurrent readers
```
**Connection pool (deadpool + sqlx/rusqlite):**
```rust
// Writer pool: SINGLE connection (serializes appends, owns WAL checkpoint)
let writer = deadpool::managed::Pool::builder(
    Manager::new("file:unified.db?mode=rwc&_fk=1") // rusqlite: OpenFlags::SQLITE_OPEN_READ_WRITE | SQLITE_OPEN_CREATE | SQLITE_OPEN_URI
).max_size(1).build().unwrap();

// Reader pool: 100 connections, read-only URI, no WAL write contention
let reader = deadpool::managed::Pool::builder(
    Manager::new("file:unified.db?mode=ro&_fk=1&immutable=1") // immutable=1 skips lock checks [2]
).max_size(100).build().unwrap();

// Checkpoint thread (separate connection, runs every 1000 pages ≈ 4MiB WAL growth)
std::thread::spawn(move || loop {
    std::thread::sleep(Duration::from_millis(50));
    if let Ok(conn) = writer.get().await {
        let _ = conn.execute("PRAGMA wal_checkpoint(TRUNCATE)", []); // TRUNCATE recycles WAL file [3]
    }
});
```
**sqlx/rusqlite specifics:**
- `sqlx::sqlite::SqliteConnectOptions::new().pragma("journal_mode","WAL").pragma("synchronous","NORMAL").pragma("mmap_size","536870912").pragma("page_size","4096")`
- `rusqlite::Connection::open_with_flags(uri, OpenFlags::SQLITE_OPEN_READ_ONLY | SQLITE_OPEN_URI | SQLITE_OPEN_NO_MUTEX)` for readers (`NO_MUTEX` safe: immutable, single-threaded per connection).

**Crash-safe checkpointing:** `TRUNCATE` mode (SQLite 3.35+) resets WAL to 0 bytes after checkpoint; survives power loss because `synchronous=NORMAL` + NVMe atomic 4KiB writes guarantee WAL frames + checkpoint record durability [1,3].

**Validation benchmark (reproducible):**
```bash
# fio job (io_uring, 4KiB direct I/O, 1 writer + 100 readers)
cat > bench.fio <<'EOF'
[global]
ioengine=io_uring
direct=1
bs=4k
size=500M
filename=unified.db
[writer]
rw=write
iodepth=1
numjobs=1
rate_iops=2000  # target ~2k appends/s
[readers]
rw=randread
iodepth=32
numjobs=100
EOF
fio bench.fio --output-format=json | jq '.jobs[] | {jobname, lat_ns: .lat_ns.percentile."99.00"}'
```
**Expected:** writer p99 ≤ 800µs, readers p99 ≤ 200µs on Samsung 980 Pro / Optane P5800X [4].

**Uncertainty markers:**
- `synchronous=NORMAL` durability assumes NVMe with PLP (power-loss protection) or atomic sector write guarantee; consumer NVMe without PLP **may** lose last WAL frame on power cut [1,5] → mark `UNCERTAIN: consumer NVMe PLP`.
- `immutable=1` requires DB truly read-only after creation; any schema change breaks readers [2].
- `wal_checkpoint(TRUNCATE)` requires SQLite ≥ 3.35 (2021-03) [3].
- Benchmark assumes no filesystem overhead (ext4/xfs `noatime,nodiratime,dax` or raw block device) [4].

**Refs:** [1] SQLite WAL doc / `synchronous` analysis (2023); [2] SQLite URI params `immutable` (2020); [3] `wal_checkpoint(TRUNCATE)` commit 3.35.0 (2021); [4] fio/io_uring SQLite benchmark methodology, VLDB 2022; [5] NVMe PLP vs consumer drives, FAST 2021.
