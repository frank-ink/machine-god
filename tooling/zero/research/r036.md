2. Minimal rules for exact two-copy detection

For a closed, versioned contract format:

Canonicalize: Resolve $ref against pinned artifacts, fix JSON Schema draft and canonicalize both documents.

Compare: Require equal canonical contract digests, or validate an explicitly authorized version migration.

Reject unknowns: Set additionalProperties: false or unevaluatedProperties: false where appropriate; reject unknown contract keywords using a restricted schema vocabulary.

Validate constraints: Compare properties, required, type, enum, items, minItems, maxItems and other supported keywords.

Resolve semantics: Apply explicit rules for field additions, deletions, type changes and compatibility direction.

Fail closed: Any unresolved reference, unsupported keyword, unexpected difference or invalid signature produces BLOCKED.

JSON Schema validation alone cannot establish equivalence between two schemas. Compatibility tools such as json-schema-diff compare accepted-instance sets, which is a different objective.

Qualification: Exact digest equality can perfectly detect byte-normalized differences, but cannot distinguish harmless changes without a defined policy. Likewise, zero observed errors on a small synthetic corpus does not establish zero production error rates.

Conclusion: Strict canonical comparison plus explicit compatibility rules is the smallest defensible architecture. A verified 50+-mutation, zero-error benchmark for the precise repo-versus-plugin problem remains unavailable.
