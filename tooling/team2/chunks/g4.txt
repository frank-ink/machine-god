 TEIL I - ARCHITEKTURTHESE

1. Executive Thesis - vom LLM-zentrierten Agenten zur
externalisierten Kognition
Heute muss ein LLM in einem einzigen Tokenstrom gleichzeitig Wissen, Sprache,
Logik, Persona, momentanes Ziel, Memory, Safety, Kontext, Strategie, Hypothesen,
Unsicherheit und Handlungsplanung repräsentieren. Selbst moderne
Agentenschichten ändern daran häufig wenig: Sie suchen Text, hängen ihn an einen
Prompt und hoffen, dass der nächste Forward Pass den richtigen internen Zustand
rekonstruiert.
Die OMEGA-Zielarchitektur zieht diese Funktionen auseinander. Langfristiger Zustand, aktive Hypothesen, offene
Widersprüche, Zielhierarchie, Vertrauenswerte, gescheiterte Strategien, kausale Modelle, Effect Authority und Reentry-
Kontinuität werden außerhalb des LLM persistent und maschinenlesbar gehalten. Das Modell übernimmt vor allem die
Operationen, in denen große Transformer besonders stark sind: semantische Transformation, Abstraktion, Simulation,
Analogiebildung, Schlussfolgerung und Sprache.

 KERNVERSCHIEBUNG

 Das LLM muss den langfristigen kognitiven Zustand nicht mehr selbst tragen. Es bekommt für jeden Denkakt genau
 diejenige Projektion des bereits vorhandenen Systemzustands, die für diesen Denkakt kausal relevant ist.

1.1 Intelligenz wird zur Eigenschaft eines geschlossenen Prozesses
Die Zielgröße ist nicht die Qualität eines einzelnen Outputs. Intelligenz wird als Qualität einer fortlaufenden Zustandsbahn
operationalisiert:

 Perception -> Hypothesis -> Prediction -> Intervention -> Error
 -> Learning -> Abstraction -> Transfer -> Reentry -> ...

Jede Kante ist messbar. Beobachtung kann von Interpretation getrennt werden. Hypothesen können Evidenz und
Gegenbelege besitzen. Aktionen können nach erwartetem Informationsgewinn gewählt werden. Vorhersagen können
gegen reale Folgen geprüft werden. Abstraktionen können auf neue Situationen getestet werden. Reentry kann zeigen, ob
Lernen den nächsten Turn tatsächlich verändert.

5. Epistemic Operational Kernel - Intelligenz als messbare
Mikrooperation
Der lange Zieltext lässt sich auf eine kleine Zahl wiederverwendbarer Operatoren
reduzieren. Diese Operatoren sind keine Philosophie, sondern Maschinenzustände
plus Übergangsregeln.

 Operator Maschinenbedeutung

 OBSERVE erfasst, was tatsächlich messbar oder sichtbar ist; Interpretation
 bleibt getrennt

 SEGMENT bildet vorläufige Objekte, Regionen, Gruppen und Grenzen

 DIFFERENCE vergleicht vorher/nachher und unverändert/verändert

 HYPOTHESIZE erzeugt testbare Erklärungen mit Scope und Unsicherheit

 PREDICT bindet Hypothese an erwartbaren Folgezustand

 FALSIFY sucht aktiv nach Beobachtungen, die eine Hypothese
 unterscheiden oder widerlegen

 INTERVENE wählt eine minimale Handlung als Messung oder Zielaktion

 MEASURE_ERROR bestimmt Prediction Error und strukturelle Relevanz

 LOCAL_UPDATE ändert nur betroffene Modellstruktur

 COMPRESS fasst Episoden zu Regeln und Regeln zu Mechanismen

 TRANSFER prüft Mechanismen in neuer Situation ohne blindes Kopieren

 PLAN erzeugt horizonabhängige Kandidaten auf Basis des aktuellen
 Modells

 REENTER macht akzeptierte Änderung kausal wirksam im nächsten Turn

6. Persistenter kognitiver Zustand - das eigentliche
Langzeitgedächtnis
Der wichtigste Schritt der Externalisierung ist ein State Store, der nicht nur Dokumente hält, sondern den aktuellen
kognitiven Zustand selbst. Der nächste Denkakt beginnt nicht bei einem Prompt, sondern bei diesem Zustand.

 State-Domäne Beispiele Zeitskala

 Observation State Messwerte, sichtbare Objekte, Deltas, Millisekunden bis Sekunden
 unveränderte Strukturen

 Epistemic State Hypothesen, Evidenz, Gegenbelege, Sekunden bis Tage
 Unsicherheit, offene Fragen

 Causal State Interventionen, Vorhersagen, Wirkungen, Sekunden bis Wochen
 Bedingungen, Gültigkeitsbereiche

 Goal State Zielhypothesen, Progress, Abhängigkeiten, Sekunden bis Projekte
 Prioritäten

 Strategy State aktive/gescheiterte Strategien, Inhibition, Turns bis Tage
 Sackgassen

 Self/Social State Identitätskontinuität, Beziehungen, Rollen, Tage bis Jahre
 Erwartungen

 Mechanism State abstrahierte Regeln und übertragbare Tage bis langfristig
 Mechanismen

 Audit State Provenance, Receipts, Versionen, Authority, dauerhaft nach Policy
 Effects

6.1 Drei Wahrheitsklassen reichen nicht - Zustände müssen sauber getrennt bleiben
Mindestens folgende Differenzen sind semantisch hart zu codieren:

 OBSERVATION != INTERPRETATION
 EVIDENCE != HYPOTHESIS
 UNKNOWN != ZERO
 UNKNOWN != ERROR
 CORRELATION != CAUSAL CLAIM
 MODEL != WORLD
 GOAL CANDIDATE != ADMITTED GOAL
 ADMITTED GOAL != EFFECT AUTHORITY

Diese Trennungen sind wichtiger als eine besonders eloquente Erklärung. Sie entscheiden, ob das System seine eigenen
Vermutungen später noch falsifizieren kann.

7. Mikro-Kognition - kleine Zustandsoperationen statt langer
Monologe
Ein großer Teil der kognitiven Arbeit sollte niemals als Sprache entstehen. Ein Modul muss keine Begründung in 300
Tokens formulieren, wenn sein Beitrag ein einzelner strukturierter Delta-Wert ist.

 example micro-outputs:

 movement_detected = true
 object_id = o_381
 delta_position = (+1, 0)
 prediction_error = 0.81
 affected_rule = rule_482
 scope = local
 contradiction_id = c_19
 new_option = action_7

Die Mikrooperation ist die eigentliche elementare Recheneinheit. Sprache wird erst dort eingesetzt, wo Semantik,
Abstraktion, Simulation oder Kommunikation von einem LLM wirklich Mehrwert erzeugen.

7.1 Lokalität der Reparatur
Fehlerkorrektur folgt einer Hierarchie. Ein falsches Ziel darf nicht automatisch die Wahrnehmung destabilisieren. Ein
Ausführungsfehler darf nicht sofort das kausale Weltmodell löschen. Jede Abweichung wird auf der niedrigsten plausiblen
Ebene lokalisiert: Wahrnehmung -> Objektbindung -> Kausalregel -> Ziel -> Plan -> Execution.

7.2 Überraschung als Lernsignal
Prediction Error ist Aufmerksamkeit, aber nicht jeder Fehler ist gleich wichtig. Ein kosmetischer visueller Unterschied kann
gering gewichtet werden. Ein Fehler in einer zentralen Regel invalidiert abhängige Pläne und erhält hohe strukturelle
Priorität.

 StructuralErrorPriority(e) = magnitude(e)
 * causal_centrality(affected_model)
 * plan_dependency_count
 * uncertainty_reduction_potential

 TEIL III - REGULATION UND KONTEXT

9. GRID als Selektions-, Regulations- und Credit-Schicht
GRID ist weder ein weiterer Agent noch eine narrative Persona. Es ist die Schicht, die
aus vielen lokalen Beiträgen einen begrenzten globalen kognitiven Zustand erzeugt.
Die vorhandene Linie Proposal -> Competition -> Selection -> Broadcast -> Uptake ->
Reentry wird zum Regulationskern der gesamten Mikro-Kognition.

 modules -> typed proposals -> competition -> selected broadcast
 ^ |
 | v
 credit <----- measured downstream effect

9.1 Vorschlag ist niemals Autorität
Jeder Spezialist darf extreme Hypothesen oder alternative Ontologien vorschlagen. Solange seine Ausgabe ein Proposal
bleibt, kann epistemische Freiheit hoch sein. Authority entsteht erst durch zugelassene Zustandsänderung; reale Effects
liegen hinter einer weiteren Grenze.

9.2 Credit ist kausal, nicht kosmetisch
Ein Modul soll nicht Kredit erhalten, weil es oft ausgewählt wird oder überzeugend schreibt. Kredit entsteht, wenn sein
Beitrag die zukünftige Zustandsbahn nachweisbar verbessert.

 credit(module_i) <- Delta(
 prediction_accuracy,
 information_gain_per_action,
 falsification_efficiency,
 transfer_success,
 goal_progress,
 recovery_time,
 unnecessary_action_rate,
 risk_adjusted_effectiveness
 )

Für belastbare Credit-Zuordnung sind Counterfactuals und Ablationen wichtig: Wie hätte sich derselbe Zustand entwickelt,
wenn der betreffende Operator nicht verfügbar gewesen wäre?

9.3 Global Workspace bleibt schmal
Die Hintergrundstruktur kann sehr groß sein. Der Broadcast muss klein bleiben. Genau diese Asymmetrie ermöglicht
tausende Spezialisten ohne tausend Stimmen im LLM-Kontext. Nur wenige Zustandsänderungen werden global relevant.

10. Dynamische Kontextkompilation - der Systemprompt
