## Gate receipt

This file is **human-maintained**. It is not written by any generator and carries no generated header.

The gate receipt is produced by:
```
python zero/capability_gate.py --json docs/zero/capabilities.md
```
The receipt is printed to stdout (JSON); it does **not** write this file.
A gate receipt must contain commit SHA, timestamp, exit codes and test counts from a named runner before any *behavioural* capability label may be promoted to `MEASURED` on gate evidence. Self-assertion (a module claiming its own label) is not `E_t` and does not promote a label.

No committed gate receipt exists in this tree; run the command above to generate one.

## Label semantics

- `MEASURED` — one of two evidence kinds, each cited in the row's Reason column:
  - **Behavioural capability** — a named test exists in source **and** passed in a recorded gate. Evidence must name: runner (`cargo test` / `npm test`), exact test path, commit SHA, timestamp, exit code, pass/fail counts. A test reference alone is not a gate receipt.
  - **Artifact presence** — a file is present in the tree at the stated path (documentation, registry source, manifest). The measurement is the file's existence at that path, verified by tree inspection; it makes **no** claim about runtime behaviour. Such rows cite the inspected path as evidence.
- `HYPOTHESIS` — intended and tracked; a test path or design doc is referenced, but no passing measurement is recorded at the last gate.
- `UNKNOWN` — no verifying measurement available at the last inspection (not implemented, presence not verified, or no gate receipt). UNKNOWN is never defaulted to 0 or 0.5 and never coerced to `MEASURED`. `UNKNOWN` does **not** assert that a file is absent; it asserts that no verifying measurement is recorded.
